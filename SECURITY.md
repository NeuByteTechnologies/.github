# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in this project, please report it responsibly.  
Do **not** open a public issue or pull request that describes the vulnerability.

Instead, use **GitHub’s Private Vulnerability Reporting** feature, available under the **Security** tab of each repository.  
This ensures the report is delivered privately and securely.

If you cannot use GitHub’s reporting feature, you may contact the maintainer directly at:

**[Your Email Here]**

Please include:

- A clear description of the issue  
- Steps to reproduce  
- Any relevant logs, payloads, or proof‑of‑concepts  
- The potential impact if known  

You will receive an acknowledgment within a reasonable timeframe.

---

## Supported Versions

This project is maintained by a single maintainer.  
Security fixes are generally applied to:

- The **latest released version**, and  
- The **main branch**  

Older versions may not receive patches unless the issue is severe.

---

## Handling Process

When a vulnerability is reported:

1. The maintainer reviews the report.  
2. The issue is reproduced and validated.  
3. A fix is developed and tested.  
4. A security release or patch is published.  
5. Credit is given to the reporter unless anonymity is requested.

---

## Scope

This security policy applies to all repositories in this organization unless a specific repository provides its own `SECURITY.md`.

---

## Best Practices for Contributors

If you contribute to this project, please:

- Avoid committing secrets, credentials, or tokens.  
- Use environment variables or secret‑management tools.  
- Keep dependencies updated.  
- Follow secure coding practices appropriate for the language or framework.  

---

## Thank You

Responsible disclosure helps keep this project and its users safe.  
Thank you for taking the time to report security issues privately and professionally.
